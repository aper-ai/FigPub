# Figure Workbench 0.4.0：组图补全与验证边界

本轮根据“期刊栏宽模板、批量拖入自动排版、A/B/C 标签、浏览器免安装使用，以及更灵活的不规则组图”的要求实现。以已有 0.3 科学工作台为基础，新增独立的物理布局内核和浏览器组图入口；没有引入 FigScan，也没有把既有分析结果转换成图片后冒充仍可计算的原始数据。

## 功能核对

| 需求 | 0.4 实现 | 实际边界 |
| --- | --- | --- |
| 期刊模板 | Nature、eLife、Cell 和通用尺寸共 11 项，保存来源与模板快照 | Cell 数值来自标明日期的 2025 官方历史指南；eLife 宽度是上传下限，不能说成固定栏宽 |
| 拖入图片自动成图 | 本机组图页批量导入/拖入后一次加入与布局；浏览器版本地导入 | 本机保留原 TIFF/PDF/多通道等支持；浏览器版接受 PNG/JPEG/WebP/受支持安全 SVG |
| 2×2、3×2 等网格 | 显式列数和行数，横/纵间距、边距，行列 0 表示自动推算 | 容量或空间不足时不提交部分布局，提示修改参数 |
| 不规则布局 | 左侧大图和顶部大图具有真实跨行/跨列单元格；支持自由移动、缩放、编组与分布 | 不包含任意层级嵌套网格求解器；已有分组自动重排前需先解组 |
| 自动编号 | A…Z、AA…，小写和数字，视觉/加入顺序，手动编号保留 | 旧工程无模式的非空标签保守归为手动；显式“全部改为自动编号”才覆盖手填 |
| 改变栏宽 | 整体适配、重新排版、只改画布三种方式；检查旋转、编号、标题、标注边界 | 不自动缩小物理字号；无法容纳时保持原状态并报错 |
| 多对象操作 | 多选、组合、复制、整体移动/缩放、对齐、等间距分布 | 本机用 Shift/Ctrl 点选和空白框选；浏览器提供独立对象选择与工具栏 |
| 撤销重做 | 配方级历史；批量布局与拖动一次撤销；失败回滚不消耗历史 | 原件、分析记录不复制进每一步历史 |
| 浏览器直接使用 | 单 HTML 包含代码、样式、字体；无运行时 CDN 或本地服务 | 是可本地打开、可静态托管的交付文件；本轮未部署公网服务 |
| 工程保存/重开 | 全部原件字节、SHA-256 清单、编辑配方、分组、模板记录 | 浏览器仅接收能正确呈现的子集；高级通道/凝胶等面板明确拒绝，当前工程不被覆盖 |
| 高质量输出 | 本机保留原有 PDF/SVG/PNG/TIFF/PPTX；浏览器导出 PNG/SVG/栅格 PDF | 浏览器 PDF 是无损 RGB 栅格封装，不能称为可编辑矢量 PDF；SVG 保留支持的矢量内容与内嵌字体 |

## 期刊规则的处理

模板目录位于 `web/modules/journal-presets.js`，完整证据见 [JOURNAL_PRESETS.md](JOURNAL_PRESETS.md)。

- Nature 当前官方图稿指南提供 89/183 mm 宽度和 170 mm 最大高度。面板小写编号 8 pt，与普通文字 5–7 pt 分开处理。
- eLife 投稿平台提供一般图至少 100 mm、整页宽图至少 200 mm、至少 300 dpi 的上传要求；本软件按下限核对。
- Cell 当前官方页面未成功返回指南，使用 2025-09-11 的发布者网页归档。85/114/174 mm 条目明确标作历史指南，另提供保持画布的自定义条目。历史规则不冒充现行强制规则。
- 通用 85/120/180 mm 保留为通用预设，不标成任何期刊的已核验官方标准。

项目保存模板快照供溯源，预检执行内置已知规则，不执行导入项目自行声明的新规则。不存在“选择某期刊后保证投稿合规”的自动认证。

## 本轮具体修复

1. 超过 26 个面板不再循环到 A；自动编号跳过已有手工编号，删除、复制后继续保持唯一性。
2. 标签具有 `auto/manual/none` 明确状态；手填、隐藏和关闭全部自动标签互不混淆。
3. 布局失败会恢复完整配方，不留下半改几何或空撤销记录。单击而未拖动不触发吸附位移、不创建历史。
4. 本机批量文件先导入并保留原件，再提交完整布局；布局失败明确告知素材仍在素材库。独立浏览器版没有独立素材库，整批导入与排版作为同一个事务，任一步失败都保持原工程不变。
5. 预览与导出读取一致的标题字号，标题/编号保持直立，图片旋转不带动这些标题。
6. 多行编号、标题、独立文字使用与 Python 一致的拆行和 1.25 em 行距；边界包含末行、下伸部及中间/末尾锚点。
7. 本机预检使用实际交付字体测量字形，分别定位图片、编号、标题和独立标注的越界；有意自定义越界仍作为 warning，不统一阻断导出。
8. 新增工程字段明确类型与单位，拒绝 NaN/Infinity、负间距、错误枚举和隐式布尔转换，保留未来扩展字段和旧工程内容。
9. 浏览器归档校验工程和原件 SHA-256、ZIP CRC、声明成员、路径与展开大小；无法呈现的高级编辑配方不会静默丢弃。
10. 浏览器 PNG 写入准确物理分辨率，PDF 使用真实毫米页尺寸和无损 RGB 流；设置导出 DPI 不改变源图实际 PPI。
11. 撤销解组后选择会重新展开为完整组合，避免随后只拖动一个成员。
12. 自动保存不写入拖动中的预览草稿；取消、失焦、Escape 会恢复原配方，提交后才保存最终位置。
13. 期刊编号字号先纳入尺寸适配，再提交模板；打开工程会清除另一个工程遗留的期刊草稿。
14. 水平、垂直与反向线条的零值/负增量在预览、属性编辑和导出中保持一致。
15. 本机拖动缩放时重绘选中面板的真实几何，编号、标题、凝胶文字保持物理字号，不在松手后跳回。
16. 本机右侧将“版式与期刊”和“对象属性”分开；批量导入后直接展示布局设置，选择面板后展示对象属性。
17. 启动诊断版本号读取同一版本常量，不再错误显示历史 0.1.0。

## 架构与性能

`layout-engine.js` 提供纯布局规划、原子提交、物理边界、编号与尺寸适配。本机 UI 与浏览器 UI 共享此实现和期刊目录，不维护两套不同的网格规则。

本机科学分析仍在原有 Python 后端执行。浏览器版在本地处理图像与工程，源文件字节与显示对象分开管理。撤销历史只保存编辑配方，图像不随每次移动重复进入历史；手势更新按动画帧合并。

可复现布局基准见 `benchmarks/composition_0.4.json`，命令为 `node scripts/benchmark_composition.mjs`。它仅测 Node 中的布局规划，不包括解码、界面绘制、导入、导出或科学计算；没有以同一数据集比较 GelFigure、ScieFig 或其他产品，不能据此宣称整体性能排名领先。

## 已执行与未执行的验证

本轮执行 Python 与 Node 自动测试，覆盖存储、分析、导出、布局、编号、分组状态、非法操作回滚、字体和安全边界。最终计数和原始日志放在 `benchmarks/validation_v0.4/`。

浏览器编解码模块在 Node 中生成真实文件，再经 Python 本机 `ProjectStore`、Pillow、PyMuPDF 和 fontTools 检查：

- 浏览器工程 → 本机打开 → 本机 DEFLATE 工程 → 浏览器解包，比较原件字节、哈希、分组和中文标题。
- PNG 的 150/300/600 ppi 元数据分别核对。
- PDF 按 89×60 mm 尺寸解析、渲染并抽取图像，RGB 原始像素一致。
- 内嵌字体字符覆盖范围与 fontTools 读取的实际字体一致。

以上是**模块、文件及跨运行时验证，不是实际浏览器界面验收**。

当前执行环境的 Chromium 启动被本地 socket 权限阻止，扩大执行权限的请求被策略拒绝；独立云浏览器与本机服务隔离，且禁止 file:// 页面。本轮没有绕过这些限制。真实浏览器脚本已提供，但 **0.4 的浏览器拖放/IndexedDB/Canvas/下载/UI 回归尚未在真实浏览器完成**；不能把 0.3 的历史 Chromium 通过记录算作本轮通过。

Windows 包重用已核验的 Windows x64 运行时，将同一冻结源代码快照放入主包 `app/` 和源码包。逐文件摘要、ZIP 完整性、PE 架构和源码一致性可在 Linux 验证；**没有执行 Windows 程序，也没有 Windows 签名或真机验收**。构建流程见 [WINDOWS_0_4_BUILD.md](WINDOWS_0_4_BUILD.md)。

## 保持不变的范围

既有 WB 自动 ROI/完整图稿、Macenko/强度分级、纤维/肌管、实例拆分合并、多曝光建议、多通道显示与定量仍在本机版。0.2 官方 Cellpose CPU 组件仍可选用，本轮没有重训模型、增加 GPU 推理或自动下载权重。

本轮未加入 FigScan、FCS 流式门控、多人云协作或自动图像配准。纯浏览器入口没有把上述本机分析伪装成可在线执行的功能。
