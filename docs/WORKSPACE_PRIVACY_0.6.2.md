# 工作区与素材隔离 · 0.6.2 候选版

本说明对应 0.6.2 的代码与验收要求。只有与候选提交绑定的完整 Windows 验收通过后，才可发布新的客户端；0.6.1 的历史结果不能替代此次验证。

## 正式客户端内容

客户端运行目录采用文件白名单，只包含应用代码、明确允许的参考 JSON、字体、图标、许可证和构建元数据。运行环境、Cellpose 引擎及模型保留各自的固定清单。文档、截图、案例图片、测试数据、工作区状态及开发脚本不进入应用目录。

完整源码 ZIP 独立保留开发代码与文档。运行文件必须与源码 ZIP 内对应文件的字节和 SHA-256 一致；最终 Windows 目录与 ZIP 还需再次通过内容边界检查。即使给实验图片重新生成了正确的清单与哈希，也不能将其加入正式应用目录。

## 启动与恢复

- 新工作区首次启动为空白。
- 已有自动保存不会静默载入图片；首页提供明确的恢复、新建和清除选择。
- 恢复前保留原自动保存，恢复时重新核验原件。选择尚未完成时阻止普通读图和写入请求，防止空白界面覆盖旧工作。
- 新建项目建立新的空工程，但不等于删除所有软件保存的原图副本。

## 清除范围与失败处理

“清除本机数据”需要明确确认。它删除软件工作区中的原图副本、登记表、当前工程、恢复备份及受控临时状态，释放内存预览和已结束任务记录。用户外部原图与另存的 `.figwork` 文件不在清理范围内。

清理会等待在途文件请求退出，并拒绝清理窗口内到达的旧上传和旧资源请求，避免删除后重新写入。正在运行或取消后尚未结束的分析任务会阻止清理。中途 I/O 失败会留下不含素材的待重试标记，重启后不恢复半删除工程；失败不显示为完成。

用户数据接口采用 `Cache-Control: no-store`。桌面客户端使用独立的私有 WebView profile，启动前清理旧的受控 profile，并在退出后清理本次 profile。清理响应明确提示退出客户端，不能把仍在运行的渲染缓存描述为已经删除。普通 HTTP 浏览器还可能需要清除其站点缓存。

此功能清理软件管理的副本，不扫描整台电脑，不承诺对历史异常退出遗留的系统临时文件进行取证级擦除。

## 浏览器组图版

启动只检查 IndexedDB 元数据，恢复由用户选择。保存、读取与清除串行执行；清除在一个事务内处理工作区和原件，失败时回滚。持久代际记录防止另一个标签页将清理前的旧工程自动写回。必要的代际值不包含图片、文件名或项目内容。

## 文档图像来源

`docs/examples/ai-wb-0.6.2/ai-generated-wb.png` 由 imagegen 从零生成，未引用用户图片。图中显式标注 AI 演示与非实验数据，只用于项目介绍，不作为算法准确率、实验定量或科研结论的依据。

`scripts/capture_privacy_documentation.py` 可在独立临时工作区导入该图片并生成真实软件截图。尚未成功执行的截图不会列为已完成验收，也不会以生成图代替软件界面截图。

## 验收重点

验证覆盖空白首次启动、显式恢复、清理确认、清理中途失败、重启不恢复已清除内容、清理期间旧上传被拒绝、外部原件字节不变、浏览器清理事务回滚及跨标签页旧保存被拒绝。最终 Windows 包还需完成真实浏览器、原生客户端及两个内置模型的既有发布门槛。
