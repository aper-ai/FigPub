# 从 GelFigure / ScieFig 迁移工程

Figure Workbench 可以通过“打开工程”读取 `.gelfig`、`.sfig` 和自己的 `.figwork`。旧格式导入会创建新的工程会话，恢复能够明确对应的原件、几何与编辑状态，并显示中文迁移提示。**请保留原工程文件：当前迁移只覆盖明确可解析的子集，不能替代完整旧工程备份。**

实现为全新 [workbench/migration.py](../workbench/migration.py)，不会运行旧应用，也不会打开旧记录中的电脑路径。格式依据是 [UPSTREAM_COMPARISON.md](UPSTREAM_COMPARISON.md) 中列明的两个固定提交，相关上游位置是 GelFigure `js/app.js::projectData` 和 ScieFig `core/sfig_io.py`。

## 1. 怎样迁移并复核

1. **先保存当前图稿。** 如正在编辑另一份工程，先导出 `.figwork`，并保留原 `.gelfig`/`.sfig` 文件。旧文件本身不会被修改。
2. **使用“打开工程”选择旧文件。** 解析、文件名与大小检查、来源哈希校验完成后才替换当前活动工程。损坏文件或校验失败会报错，当前工程保持原状。
3. **逐项查看迁移提示。** 界面会列出需要复核的内容；提示也保存在 `project.settings.migration_warnings`，随新工程再次保存。
4. **确认素材完整。** 核对原件数、文件名、位深、尺寸和帧数。相同文件字节会合并为一个 SHA-256 素材，但不同旧归档路径仍记录在 `asset.metadata.legacy.archive_names`。同名但内容不同的原件仍是不同素材。
5. **对照原图检查图稿。** 特别检查裁切范围、方向、翻转、隐藏泳道、Marker 单位、物理宽度、中文/特殊字符及比例尺；多个条带或显微图拆分后的排版需要逐项确认。
6. **重新运行分析。** 在 WB 中设置实验、样本、生物重复、技术重复、曝光与目标/内参身份；在 qPCR 中确认字段、参考基因和对照；显微分析确认像素标定、通道、阈值及 ROI。旧显示调整不会被当作新测量输入。
7. **预检、保存并再打开一次。** 检查来源、像素与物理尺寸、有效分辨率、饱和、字体和画布范围，再导出 `.figwork`。重新打开后核对原件和结果仍可读取，再用于继续编辑或分享。

哈希校验用于比较文件字节和保存时的记录；哈希一致本身不证明图像的真实性，也不证明实验设计或测量结论正确。

## 2. GelFigure `.gelfig` 支持矩阵

该格式可为 gzip 压缩 JSON 或明文 JSON。当前支持 `gelfigProject: 1`，其中 `source.bytes` 是原件的 base64 数据，`source.sha256` 用于核对来源。

| 旧内容 | 当前处理 | 需要用户确认的内容 |
|---|---|---|
| 保存时选中的原始图像 | 解码嵌入数据，校验已有 SHA-256，按实际文件重新检测尺寸/位深，原字节保持不变 | `.gelfig` 本身只包含选中曝光；其他曝光必须另行导入 |
| gzip / 明文 JSON | 均支持，使用有上限的解压与 JSON 解析 | 格式版本与数据必须有效 |
| 原件 SHA-256 缺失 | 给出告警，为读入字节建立新哈希 | 无法据此核对旧保存记录；已有哈希不匹配则直接拒绝 |
| 没有方向变换或纠偏的裁切 | 将 `{x,y,w,h}` 映射到原图 `{x,y,width,height}` | 超出真实原图边界时恢复完整原图并提示重新裁切 |
| `orient` 或 `rotation` 非零 | 恢复完整原图；原裁切、泳道和标注状态保留供核对 | 旧坐标经过方向变换/纠偏，不能直接套用为原图 ROI；需要重新确认 |
| 无变换的泳道位置、名称 | 恢复原图像素中心与纯文本名称 | 富文本字体、斜体等不承诺逐项一致 |
| 隐藏泳道 | 恢复隐藏索引；新导出显示拼接线 | 隐藏后自由标注位置不能按旧拼接前坐标直接复用，因此保留旧状态供重新放置 |
| Marker 条带与单位 | 恢复可见且未排除的锚点；保留 bp/kb/kDa，kb 数值按 bp 转换 | 多套 Marker 统一在图右侧显示；混合单位与位置变化会提示复核 |
| 色阶、gamma、反相 | 对可靠的无符号整数来源，将归一化色阶换算到原始数值范围 | 超出支持范围的 gamma、无法对应的源数值范围会恢复默认显示并提示；原始像素不变 |
| 物理宽度、面板字母 | 使用保存的毫米宽度，或按原自动泳道宽度规则计算 | 自动边距、文字避让和字体测量不承诺与旧版完全一致 |
| 基础矩形、侧/下方文字、泳道分组、条件文字 | 在坐标可可靠映射且没有隐藏泳道时转成可编辑画布对象 | 与旧图对照确认边距和多行条件布局 |
| 箭头、侧边括号、复杂排版和富文本 | 保留参数并给出告警，尚未逐项转换 | 在新画布重新建立对应标注 |
| 自定义 Ladder、旧初始状态等 | 作为旧状态保存，当前不自动合并到新 Ladder 目录 | 使用实际厂家和胶体系重新确认标定 |

这些行为由 [GelFigure 迁移函数](../workbench/migration.py) 与 [位深、裁切、坐标变换测试](../tests/test_migration.py) 覆盖。下载的 `.gelfig` 与浏览器本地多曝光历史是不同保存范围，迁移器无法恢复文件内从未包含的曝光数据。

## 3. ScieFig `.sfig` 支持矩阵

`.sfig` 是 ZIP 工程，通常包括 `manifest.json`、`project.json`、`composer/*.json` 和 `data/` 下的原件。清单中项目与 Composer 的哈希基于规范化 JSON，原件哈希基于实际字节。本实现分别检查这些记录。

| 旧内容 | 当前处理 | 限制与复核点 |
|---|---|---|
| 清单、项目、Composer JSON | 校验结构与已有哈希；支持旧清单中能唯一定位的 basename 原件键 | 声明文件缺失、路径歧义或哈希不一致会拒绝；缺少历史哈希会明确告警 |
| 多个已嵌入原件 | 收集全部支持格式的 `data/` 原件和声明来源 | 原文件路径不会被读取；未嵌入或无法唯一匹配的引用需要重新关联 |
| 相同内容的多个归档成员 | 按完整 SHA-256 去重，保留所有归档路径 | 相同 basename、不同内容不会合并；显微 canonical 路径与哈希用于准确区分 |
| WB `band_strips` / 旧 `crops` | 每个原件与原图裁切恢复为独立子图，保留可对应翻转与蛋白标题 | 旧旋转会扩展画布，新规则不同，因此旋转只保留参数并提示复核 |
| WB 旧亮度/对比度 | 不强行映射成原始位深显示参数；旧值保留 | 旧处理作用于 8-bit 显示，与原始强度色阶不能简单等同 |
| WB 分组、泳道文字、模块内复杂排版 | 保留完整旧状态并告警 | 当前不承诺还原模块内部每个布局对象 |
| 荧光 / IHC / 明场原图 | 按 canonical 路径、哈希或唯一嵌入文件名恢复支持的原件 | 可可靠对应的逐通道名称、伪彩、范围、显隐和分屏迁入新配方；旧阈值结果需重新计算 |
| 显微标定 | 保存 `um_per_px`、`um_per_px_x`、`um_per_px_y` 和标定来源；可对应的比例尺长度恢复 | 比例尺显示位置使用新画布右下角；标定与视觉比例尺必须重新核对 |
| 多页/多帧原件 | 全部原始文件字节保留 | 迁移子图默认第 1 帧，原工程所选帧需复核 |
| 外部 PNG/TIFF/JPEG/SVG/PDF 等面板 | 已嵌入来源恢复为新素材及图像子图 | 只处理支持且能验证的格式；不访问外部电脑路径 |
| Composer 画布 | 恢复宽、高毫米与背景 | 活动图稿优先；多图稿中的其他图稿保留旧状态 |
| Composer 子图引用 | 恢复毫米位置、尺寸、字母、可见/锁定状态 | 包含多个图像/条带的旧面板拆为独立子图，并均分旧引用区域，复杂组合需重排 |
| Composer 文字、直线、矩形 | 转为基础画布对象，保留可对应的毫米位置、字号、颜色和线宽 | 富文本、斜体、旋转、填充及跨图层叠放需要复核 |
| 箭头、椭圆等其他形状 | 原状态保留并告警 | 当前基础标注模型尚未完整映射 |
| qPCR 表格与旧统计图 | 支持的嵌入原始表格保留；旧分析/图表状态保留为历史 | 需要重新运行分析，再生成新的结果图 |
| 缓存 `analysis.npy` 或其他未知二进制 | 明确告警并跳过二进制导入 | 不反序列化 pickle；请从原程序导出支持的 TIFF/表格后补入 |
| 没有 Composer 的工程 | 可恢复图像放入默认网格 | 默认网格是便于继续编辑的新布局，应重新排版 |

目前可注册的原件格式为 `.png`、`.tif`、`.tiff`、`.jpg`、`.jpeg`、`.bmp`、`.webp`、`.svg`、`.pdf`、`.csv`、`.tsv` 和 `.xlsx`。对复杂厂商格式、其他存储容器及未嵌入来源，请先在原程序导出原始 TIFF 或支持的表格。改变扩展名不会转换实际文件格式。

## 4. 旧结果、原件和新测量分别保存

新工程的 `assets` 保存实际读入、验证过的原件。`panels.crop` 使用原图像素；画布位置和尺寸使用毫米。显示调整只改变展示，不能修改原件字节，也不会成为分析数组。

历史项目和 Composer 状态在大小允许时写入 `settings.migration.legacy_snapshot_json`。它是惰性文本，只供检查和后续适配，既不执行代码，也不会把里面的旧 asset ID 当成当前有效素材 ID。旧 `.gelfig` 的原件 base64 不重复写入该 JSON；原件已经单独保存。超过 6 MB 的完整历史状态会明确提示未嵌入，应继续保留原工程。

旧测量、分割和统计结果不会填入新 `measurements`。这样可避免把不同坐标、位深、背景方法、重复定义下的旧数字当成新算法已经验证的结果。用户重新运行分析后，新记录保存该次参数、来源素材 ID、工程修订与实际结果；生成统计图时继续关联这些记录。

统计图标签目前转换成矢量路径以固定中英文字体外观，SVG 描述元数据保留真实观测值和重建参数。要改标签或图型，应从已保存的结果重新生成图表；这些路径不等于可单独编辑的文字。组图画布上另行添加的基础文字对象仍按本项目画布模型编辑。

## 5. 常见提示应该怎样处理

| 提示类型 | 实际含义 | 建议操作 |
|---|---|---|
| SHA-256 不匹配 | 文件字节或 JSON 已不符合旧保存记录 | 找回正确的原工程或从原程序重新保存；不要通过修改清单掩盖差异 |
| 未声明历史哈希 | 旧格式没有足够记录可供比较 | 核对原件，再保留新工程建立的来源哈希 |
| 无法唯一恢复素材引用 | 文件未嵌入、名字冲突或当前不支持 | 在素材区补入正确原件，并逐个重新关联/重建子图 |
| GelFigure 变换后坐标 | 旧裁切属于方向变换/纠偏后的画布 | 对照原图重新裁切，重新确认泳道与 Marker；旧坐标保留供查看 |
| 旧 WB 显示调整未对应 | 旧 8-bit 调整与新原始数值色阶不同 | 调整展示色阶，分析仍使用原始数组 |
| 多图/多条带均分区域 | 原件恢复成功，复杂组合布局只作基础拆分 | 调整每个子图的毫米尺寸和位置，再复核标签 |
| 多页/多帧默认第一帧 | 原件完整，但旧选择未自动恢复 | 确认需要的页/帧后再测量和导出 |
| `.npy` 未导入 | 当前安全解析子集不加载该格式 | 在原程序将需要的数据导出为原始 TIFF，再补入 |
| 旧结果需要重新分析 | 历史数字没有被当成新测量 | 确认实验身份与方法，运行新分析，检查实际结果与 QC |

## 6. 资源上限与安全行为

当前实现使用以下有界读取策略；超限会报错或给出明确保留范围提示，不会无提示截断原始像素：

- 单个原件上限为 128 MiB；上传工程和 ZIP 展开总量上限为 512 MiB；ZIP 成员最多 1024 个。
- 新工程 JSON 上限为 16 MiB；可嵌入的旧状态文本上限为 6 MiB。
- 每个新工程最多 256 个不同原件、1000 个子图和 5000 个基础标注；凝胶 Marker 数量也有上限，避免异常结构造成组合膨胀。
- 图像像素上限为 6000 万，解码内存、PDF 页数、表格行数等仍接受新素材验证器的限制。
- ZIP 路径遍历、绝对成员路径、符号链接、加密归档、重复成员、重复 JSON 键、非有限数及过深 JSON 均被拒绝。
- 不使用 `extractall` 解压到旧路径，不运行旧脚本，不调用 pickle，也不读取 `image_path`/`source_path` 中的外部路径。
- 临时检查文件使用程序生成的安全文件名；活动工程只有在解析和素材校验通过后才会更换。旧运行中的分析任务不会附加到新会话。

具体限制来自 [migration.py](../workbench/migration.py)、[storage.py](../workbench/storage.py)、[models.py](../workbench/models.py) 与 [jobs.py](../workbench/jobs.py)。字体缓存是图表渲染的独立运行缓存，不属于旧原件恢复；缺少支持字形的字体会明确报错。

## 7. 测试覆盖与验收边界

[tests/test_migration.py](../tests/test_migration.py) 包含迁移回归测试，覆盖明文/gzip `.gelfig`、16-bit 字节一致、色阶和裁切映射、变换坐标告警、多来源和同名显微原件、非等向标定、毫米排版、基础标注、哈希损坏、路径遍历、符号链接、外部路径不读取、不加载 `.npy`/pickle、解压上限、损坏 PDF、畸形数值，以及 `.figwork` 往返和失败不改变活动工程。

测试 fixture 按上游真实保存结构构造，图像像素是可复现的合成 TIFF。它们能验证容器解析、来源和几何契约，不意味着已覆盖每一份历史用户工程。迁移真实工程后的原图、排版和测量复核仍是验收步骤的一部分。

开发者可运行：

```bash
python -m pytest tests/test_migration.py tests/test_storage.py tests/test_api.py -q
```

API 接口为 `POST /api/project/open`，multipart 字段为 `file`。迁移器返回结构化 `MigrationResult(project, sources, warnings)`；后端再次通过标准素材验证流程注册原件，然后生成新会话身份并持久保存。[服务实现](../workbench/server.py)；[工程存储](../workbench/storage.py)。

## 0.2：多通道迁移

标准 fluorescence 通道以实际嵌入原件的 series 0 / frame 0 为来源，恢复 name、pseudocolor、display_min/max、visible 和 merge/single/split；split 同时包含 Merge。旧显示黑白点能线性换算时合并入新原始强度范围。旧单通道画布临时选择没有可靠保存字段时恢复首个可见通道并提示复核。

旧 RGB composite 保持自然 RGB；旧 auto_single_signal 的合成强度投影不会被错误映射为某一个 RGB 分量。不能可靠对应的原通道索引、跨图派生投影、显示降噪/非线性增强/背景移除仍保留在历史状态并明确提示。原始字节和旧工程状态完整保留，旧测量结果不会被当作已经在新算法中重算的结果。
