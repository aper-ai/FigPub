# 0.3 实例人工复核

本模块把经典核分割、Cellpose、纤维横截面及肌管分析的实际整数标签保留下来，提供人工拆分、合并、删除和补画。原图与最初的自动分割结果均保持不变；修订是可重放的编辑记录。

## 操作

1. 选择原始测量通道并完成一次分析。结果必须已保存且参数未过期。
2. 在分析结果下面打开“实例人工复核”。工作台显示实际测量通道的原图和实例轮廓，点击选择使用无损标签像素，不使用近似轮廓判断命中。
3. “两点拆分”：在同一对象内部点两个不同的原图位置。两个种子在对象内部进行等高面分水岭生长，使两点共同约束拆分区域；拆分保留该对象的全部前景像素，不删除一条切割缝。
4. “合并所选”：点选两个或多个实例后合并。默认要求它们相邻。明确勾选“允许合并不相邻区域”后可保留间隙合并，操作记录会写明连通部分数量。不会自动填充间隙。
5. “删除所选”把所选标签改为背景；“多边形补画”逐点描画后提交，“矩形补画”拖动后提交。补画不得覆盖既有实例，不得越过原分析 ROI 或无效源像素。自交多边形会被拒绝。
6. 使用工作台的撤销、重做或“回到自动分割”。回到原始结果保留重做历史；在撤销位置追加新操作会截断后面的重做分支。
7. 下载复核后的 CSV 和 uint32 标签 TIFF。保存 `.figwork` 后，原始标签与操作记录随工程保存；重新打开后再进入复核工作台，会从原始分割重放已保存操作。

上方普通分析结果保留自动分割记录。需要人工修订后的数据时，使用复核工作台内的“下载复核后 CSV”或“下载实例标签 TIFF”，以明确区分两个版本。

对象 ID 不因一次删除而被下一个新对象复用。拆分保留原 ID 并分配一个新 ID；合并保留所选 ID 中最小者。操作记录保存输入/输出 ID、前后前景面积和坐标，可追溯来源。

## 测量与纤维联动

经典核分割与 Cellpose 的面积、质心、外接框、等效直径、平均强度及积分强度重新读取原始通道和修订后的真实像素掩膜。提供像素标定时按实际 x/y 标定换算物理面积。显示黑白点、颜色和 Gamma 不参与测量。

纤维横截面及肌管的人工修订调用 `fibers.recompute_fiber_result`，重新计算其专用指标、核归属及分型；不会用一般细胞计数代替完整纤维结果。IHC 光密度分级是像素分析，不自动伪装成可人工修订的细胞实例计数。

导入纤维标签的几何独立于强度通道。强度包含非有限像素时仍可复核标签面积，强度指标只计有限样本并保留 `valid_intensity_pixels`；不会把缺失强度当作零值。这与直接从有效强度像素产生的经典核／Cellpose 标签有所区别。

工作台显示复核前后实例数、前景面积、当前历史游标及对象明细。拆分和合并检查前景并集守恒；补画和删除明确改变实例掩膜的覆盖范围，原始图像强度始终不变。

## 文件与边界

- 标签使用二维、原始像素网格的 uint32，背景为 0，正整数代表实例。持久化采用有上限的 zlib + Base64 无损压缩。
- SHA-256 同时绑定标签字节、ROI 尺寸、原图坐标原点及原图尺寸；不能只更改原点而保持旧哈希有效。
- 复核单个 ROI 最大 1600 万像素、100000 个实例、压缩后 2 MiB；超限时保留分析结果，明确提示缩小 ROI 后再进行人工复核。不是截断标签或以轮廓近似代替标签。
- 每个分析记录最多 200 步操作；单次合并最多 32 个实例；补画多边形最多 512 顶点。无效、越界、过期、重复操作 ID 或不匹配来源会明确拒绝。
- 为保持显示流畅，复核窗口同时显示前 1000 个及已选对象的轮廓；点选仍使用全部标签。每个结果返回的对象明细仍受分析器的 `max_objects` 上限约束，完整数量与明细截断警告都会保留。
- 标签 TIFF 保存 ROI 的实际尺寸，描述元数据包括 `roi_origin_xy`、`source_shape_yx`、分割方法与复核操作；它不是经过拉伸的彩色预览。
- 工程只在 `settings.instance_reviews[measurement_id]` 保存小型操作历史和游标，不反复复制衍生标签结果。每次复核都检查工程 ID、版本、测量 ID 和基准标签哈希；计算期间工程发生改变时结果不会覆盖当前编辑。
- “取消等待”中止当前浏览器请求并丢弃未应用的结果。服务端已进入的原生计算可能在返回后才释放计算槽位；它不会在后台写入项目。核心同时接受取消事件，可在操作重放及测量阶段检查取消。

## 开发接口

`workbench.instances` 提供：

```python
encode_instance_mask(labels, origin=(x, y), source_shape=(height, width))
decode_instance_mask(payload)  # read-only uint32 YX array
attach_instance_mask(result, labels, origin=(x, y), source_shape=(height, width))
review_instances(base_result, original_image, operations, cursor=None,
                 params=None, cancel_event=None)
label_tiff(reviewed_result)
```

复核是纯计算。API 从已保存的不可变测量记录读取原始数据；不接受客户端伪造的像素数组或基准结果。`POST /api/instances/review` 和 `/api/instances/export` 的请求含 `project_id`、`revision`、`measurement_id`、`base_mask_sha256`、`operations`、`cursor`。

前端模块 `web/modules/instance-review.js` 使用独立原图 SVG，不接管普通 ROI 手势。`bindInstanceReview` 注入现有项目状态与请求函数，`renderInstanceReview` 渲染工作台，`reviewedInstanceResult` 返回与当前保存历史对应的衍生结果缓存。

## 验证

数值测试见 `tests/test_instances.py`：原图未改、真实积分一致、原点/孔洞/稀疏 ID 保真、拆分合并面积守恒、撤销重做确定性、补画几何、取消、哈希篡改/解压上限以及 TIFF 元数据。

前端纯逻辑和浏览器解码测试见 `tests/test_instance_review.mjs`。真实浏览器流程见 `tests/browser_instance_review.py`：导入明确合成的 uint16 图像，运行实际经典分割，再用鼠标拆分/合并/删除/补画，下载并检查 CSV/TIFF，保存并重开工程。没有注入预制分析结果。

这些测试验证编辑与测量链条，不是生物学分割准确率或 Windows 实机验收。

本轮实例专项实际通过 **40 项 Python、6 项 JavaScript、6 个真实浏览器场景，浏览器页面异常为 0**，并通过 Oxlint。浏览器除上述流程外，还实际验证多边形补画、拒绝覆盖已有实例，以及失败操作不增加历史。完整组件截图已目视核对。独立模型运行验收以总项目的 Cellpose 验证记录为准，不能用经典核分割流程代替模型执行证据。
