# 启动入口与运行目录

本文记录源码入口和 Windows 便携包共用的启动行为。实际交付包的文件名、构建方式与验收状态，以主说明及 Windows 分发说明为准；这里不代表已在真实 Windows 系统上完成运行验收。

## 资源和工程放在哪里

便携版使用自带 Python 运行 `app/run.py`。网页、字体和基准文件从同一个 `app/` 目录中的 `web/`、`resources/`、`benchmarks/` 读取，不依赖用户从哪个文件夹双击程序。源码运行采用相同规则；如果使用 PyInstaller 构建，则读取其 `_MEIPASS` 资源目录。

工作工程默认保存在当前用户目录：

| 系统 | 默认目录 |
|---|---|
| Windows | `%LOCALAPPDATA%\FigureWorkbench` |
| macOS | `~/Library/Application Support/FigureWorkbench` |
| Linux | `$XDG_DATA_HOME/figure-workbench`，未设置时使用 `~/.local/share/figure-workbench` |

原件、自动保存和启动记录不会默认写进程序安装目录。`--data-dir` 或 `FIGURE_WORKBENCH_DATA` 可以明确指定其他可写工作目录。`run.py` 不生成应用目录中的 Python 字节码缓存；图表缓存使用用户工作目录下的 `cache/`。用户已经明确设置的缓存环境变量继续生效。

## 启动、重复打开与退出

程序仅监听 `127.0.0.1`。优先使用端口 `8765`，端口被其他程序占用时选择可用端口，并显示实际地址。服务启动成功后才打开默认浏览器；浏览器启动失败会显示可手动打开的本机地址。

每个工作目录有操作系统持有的单写锁。重复打开同一工作目录时，启动器会核对现有服务的实例标识，然后打开现有页面，不会创建第二个工程写入进程。残留的 `instance.json` 本身不能占用锁，也不会使启动器盲目打开已被其他程序复用的端口。

控制台版本使用 `Ctrl+C` 退出。正常退出会清理实例记录、关闭监听端口并释放锁；异常终止后，操作系统也会释放文件锁。关闭浏览器页面不等于退出本地服务。

## 启动错误与日志

每次启动写入 `<工作目录>/logs/launcher-<PID>.log`。默认 Windows 路径为 `%LOCALAPPDATA%\FigureWorkbench\logs\launcher-<PID>.log`。单份日志的轮转阈值为 2 MiB，保留一份备份，并清理较旧日志以保留最近 20 个文件。

如果指定工作目录无法写入，启动日志会尝试用户默认目录，再尝试系统临时目录；错误提示显示实际日志位置。程序不会因此把工程悄悄改存到另一个目录。

启动错误返回非零退出码，并保留详细异常堆栈。无控制台的 Windows Python/冻结版本另外调用原生错误消息框；当前便携版是否带控制台，由外层原生启动器决定。这里没有增加后台退出接口或新的网络控制端点。

`run.py --check` 检查必要网页、字体文件及运行依赖能否导入。缺少资源会明确失败；包元数据未随冻结程序包含时，会报告模块可导入而不是将元数据缺失误判为依赖缺失。此检查不能替代具体操作系统上的完整编辑、分析和导出验收。

## 验证范围

自动回归覆盖了资源目录与用户数据分离、模拟冻结资源路径、单写锁、实际子进程的端口冲突与重复启动、启动失败后的锁/端口清理、无控制台错误处理分支，以及本地服务身份核对。真实网络与进程验证在 Linux 上运行；Windows 路径和消息框分支的单元测试不等于 Windows 真机验证。
